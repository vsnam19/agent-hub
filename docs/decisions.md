# Decision log

Every design decision for agent-hub, newest last. Each entry says what was decided, why, and what was rejected, so
the reasoning can be tracked and revisited later. Decisions marked **(user)** were made by the owner; the rest were
made by the orchestrating agent in autonomous mode and are open to challenge.

| ID | Date | Decision | Why | Rejected |
|----|------|----------|-----|----------|
| D-001 | 2026-10-08 | **(user)** agent-hub is its own repository (`~/Workspaces/tools/agent-hub`); vsndevenv only installs and wires it, through a module, later. | Different domain (agent runtime vs. machine setup), different release pace, used inside any project. Same split as khub. | Building it inside vsndevenv; extending `tools/ai/myai` (that project builds a coding agent with its own sandbox, a larger and different problem). |
| D-002 | 2026-10-08 | **(user)** Shape: a CLI core, a thin MCP server over it, and skills. v1 ships the CLI and skills; the MCP server comes later. | The CLI is testable with pytest, callable from the vsndevenv GUI later, and runs anywhere Bash exists. | MCP-only (hard to test or run by hand); skill + ad-hoc scripts only. |
| D-003 | 2026-10-08 | **(user)** One directory per agent (adapter + `agent.toml` + `profile.md`); the master `orchestrate` skill names no agent and reads the pool at run time. Build the agents first, the master last. | Adding an agent to the pool must not touch the master. Each adapter is testable alone. | A master skill that chains per-agent skills (skill loading is description-driven, chaining is unreliable). |
| D-004 | 2026-10-08 | **(user)** Agents are picked by **role**, each role an ordered chain of `agent:model`, combined with quota: the CLI walks the chain and skips links on cooldown. | Matches the existing routing rule (Opus 4.6 → Sonnet 4.6 → Gemini → Sonnet 5.5) and makes it data, not prose. | Pure priority order; Claude choosing every time. |
| D-005 | 2026-10-08 | **(user)** v1 roles: `implement` and `review`. Research stays with the orchestrator. | Implement is the established delegation; review gives a cross-model second opinion and replaces the antigravity plugin's `review`. | Implement only; adding research. |
| D-006 | 2026-10-08 | **(user)** Jobs run in the foreground until done; the caller backgrounds them (Claude Code's `run_in_background`). Every job leaves a directory. No daemon. | The harness already notifies on exit, so no polling and no token cost; a job directory keeps the record for later readers (GUI, MCP). | Detach-and-poll (wastes turns); a queue daemon (heavy for v1). |
| D-007 | 2026-10-08 | **(user)** The CLI never creates worktrees. `implement` refuses unless `-d` is a git work tree on a non-default branch. | Worktree creation belongs to the orchestrator's workflow; the CLI only guards. | `--worktree <branch>` creating one. |
| D-008 | 2026-10-08 | Fallback to the next link happens **only** on quota, auth, model-unavailable or agent-not-installed, and only while the work tree is unchanged since the job started. A generic failure, a timeout, or quota hit after edits stops the job. | Starting another agent on a half-edited tree mixes two agents' work; the orchestrator must look first. | Falling back on every failure. |
| D-009 | 2026-10-08 | Quota puts `agent:model` on cooldown in `$XDG_STATE_HOME/agent-hub/cooldowns.json` until the reset time the agent printed, else for `quota_cooldown` (default 60 min). Auth failures are not cooled down; they are reported. `agent-hub pool --clear` lifts a cooldown. | Later jobs skip a dead link without paying for a failing call; auth needs a person, not a timer. | No memory between jobs; probing quota before every job (costs a call). |
| D-010 | 2026-10-08 | The brief always travels as a file. codex and claude read it on stdin; agy (prompt only via `-p` argv) gets a fixed one-line prompt naming the brief's path, with the job directory added via `--add-dir`. | Brief text never appears in `ps` or in argv quoting. | Brief as an argv string. |
| D-011 | 2026-10-08 | `implement` briefs must contain an `## Input` and an `## Expected output` heading; the CLI refuses otherwise (exit 2). | Encodes the existing briefing rule so no brief reaches an agent without them. | A warning only. |
| D-012 | 2026-10-08 | `review` runs read-only where the agent supports it (codex `-s read-only`; claude with read and `git diff/log/show` tools only; agy `--mode plan` without skip-permissions) **and** always under a work-tree fingerprint check; a change fails the job (exit 5). | Not every agent has a real read-only mode; the fingerprint is the guarantee. | Trusting each agent's mode. |
| D-013 | 2026-10-08 | Implement permissions: agy `--dangerously-skip-permissions`; codex `-s workspace-write` with network on and the repository's git common dir added (a worktree's `.git` lives outside it); claude `--permission-mode bypassPermissions`. | Headless agents cannot ask; codex keeps a real sandbox because it has one. The guard in D-007 bounds the blast radius to a feature branch. | codex `--dangerously-bypass-approvals-and-sandbox` (kept as the fallback if workspace-write breaks real tasks). |
| D-014 | 2026-10-08 | The agent's environment drops variables whose names look like secrets (`TOKEN`, `SECRET`, `PASSWORD`, `API_KEY`, `PRIVATE_KEY`, `CREDENTIAL`, and `FNOX_`/`AWS_`/`GH_`/`GITHUB_` prefixes) unless the agent's `agent.toml` lists them in `env_passthrough`; Claude Code session variables (`CLAUDECODE`, `CLAUDE_CODE_*`) are unset for every child. | Agents authenticate from their own config files; nothing from the orchestrator's environment needs to leak. A nested `claude -p` must not think it runs inside the parent session. | Passing the environment through; an allowlist (breaks PATH, locale, tool config). |
| D-015 | 2026-10-08 | Python ≥ 3.12 with uv, no runtime dependencies (stdlib `argparse`, `tomllib`, `json`, `subprocess`), pytest + ruff, a `justfile` with `lint` and `test` — the same conventions as vsndevenv's `tools/runner`. | One toolchain across the user's projects; nothing to install beyond uv. | click/typer (a dependency for little gain). |
| D-016 | 2026-10-08 | Tests never run a real agent: fake `agy`, `codex` and `claude` executables on a test-only `PATH` play scenarios (ok, quota, auth, empty, slow, write-during-review). Real agents are exercised only by `just smoke`, run by hand. | Real calls cost quota and are non-deterministic. | Mocking `subprocess` (would not test argv, stdin, process groups or timeouts). |
| D-017 | 2026-10-08 | Agent output goes to files in the attempt directory (stdout, stderr, reply), never a pipe the CLI reads while the agent runs. Timeouts kill the agent's whole process group. | agy's MCP children can hold a pipe open after agy exits (seen by the antigravity plugin, its issue #37). | Capturing through pipes. |
| D-018 | 2026-10-08 | Per-agent skills are not in v1; `agent-hub profile <agent>` prints the agent's `profile.md` for the orchestrator. | The master needs the profiles; direct per-agent skills add nothing yet. | Shipping a skill per agent now. |
| D-019 | 2026-10-08 | v1 installs the `orchestrate` skill by hand (symlink into `~/.claude/skills`), documented in the README. Installing skills and MCP servers into each agent's own config is the **hub** spec, next. | Keeps v1 to the orchestration loop. | Building the hub installer now. |
| D-020 | 2026-10-08 | Execution: each plan task is one brief to agy (strongest model with quota, then the Sonnet 5.5 subagent), on its own branch in a worktree under `.worktrees/`; the orchestrator verifies (`just lint && just test`, diff read, assertion scan) and merges locally into `master`. No remote yet. | The owner's standing rule: the orchestrating model plans and verifies, agents implement. | The orchestrator implementing directly. |
| D-021 | 2026-10-08 | Review never gives an agent a shell. The CLI writes `git diff <base>...HEAD` to `<attempt_dir>/diff.patch` and the review preamble points at it; claude reviews with `--allowedTools Read,Grep,Glob` only (plus `--add-dir <attempt_dir>`). Replaces the `Bash(git diff:*)`-style allowlist from spec §8.3. | A security review found that `git diff/log/show --output=<file>` writes arbitrary files, so a git-prefix allowlist is not read-only, and writes outside the work tree escape the D-012 fingerprint. | Keeping the git allowlist; denying `--output` by pattern (other write-capable flags exist). |
| D-022 | 2026-10-08 | A job's `pid` file records the CLI's pid **and** its process start time (`/proc/<pid>/stat` field 22); `cancel` signals only when both still match, otherwise it marks a `running` job `cancelled` without sending anything. | A security review found that a crashed job's pid can be reused by an unrelated process, which `cancel` would then kill. | Pid only; checking the command line (spoofable, and the CLI may run under different launchers). |
| D-023 | 2026-10-08 | Human-readable output (`run`, `show`, `jobs`) strips control characters other than `\n` and `\t` from agent-provided text when stdout is a terminal; `--json` output is unchanged (JSON escapes them). | Replies are untrusted model output; raw escape sequences could rewrite the terminal or hide text (security review). | Stripping always (would alter piped output that tools may parse). |
